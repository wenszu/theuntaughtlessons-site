- Built October 1, 2026: a third pass on the full report, focused on the header/footer system, a true full-bleed cover/closing/section-opener treatment, and a genuine Chrome print-engine bug found and worked around in the process. **The bug, for anyone touching this CSS again:** redeclaring the `margin` property inside a named `@page <name> { }` rule — to any value, including `0`, including the exact same value as the page's own default margin — silently corrupts the available-width layout calculation for unrelated content elsewhere in the same paginated document. It does not affect the named page itself; it affects *other* pages, inconsistently, in a way that looks exactly like a flexbox/grid sizing bug (paragraph text truncated mid-word with the missing characters absent from the PDF's own text layer, not just visually clipped). It took a full isolated bisection against a standalone reproduction file to find, down to toggling one `@page cover{ margin:0 }` block on and off. The fix: never redeclare `margin` (or `size`) on a named page — only margin-*box* properties (`@top-center{content:...}` etc.) are safe to override there. True full-bleed pages (cover, closing) now use a negative CSS margin on the *element itself* (pulling it past the page's own untouched default margin) instead of a zero-margin named page; per-part running header text uses named pages for `@top-center` content only, with no margin/size redeclaration. Also this pass: a real 3-zone running header (UTL wordmark, current part name, "Executive readiness report") and a slim navy 3-zone footer (UTL name, "Prepared for [name], [date]" or just "Prepared [date]" with no name placeholder, page X of Y), both built as genuine CSS `@page` margin-box content rather than in-flow page elements, so they repeat on every page except the cover and closing automatically, with nothing stranding a near-empty page the way the previous pass's in-flow header did; a full-bleed navy cover and closing page bookending the report, with the score and profile name added to the cover; five navy "part opener" bands (large gold part number, part name, one-line summary) opening each of the five contents parts, reusing the exact navy/gold intensity of the executive summary card so every page now matches that page's polish; axis labels drawn directly on the radar chart's five points (previously only in the side legend) plus a short "filled vs. hollow" caption; small bar visuals added to every strength and growth-edge card; the "Decision making" section given the same result-step badge treatment as every other section instead of sitting in an unlabeled card; the contents page rebuilt with large part names and true vertical sub-bullets beneath each (the previous layout ran sub-items in a single horizontal line, which is what prompted this pass). **Not done, flagged instead of faked:** real page numbers in the contents list. Chrome's print engine does not implement `target-counter()` (confirmed by direct test — the content property silently resolves to nothing), so there is no CSS-only way for a reference early in the document to know what page a later section will land on; the contents page lists parts and sub-items without page numbers rather than showing fabricated ones. A second, unrelated layout bug was also found and fixed in the same pass: `.famous-grid` and `.two` used `grid-template-columns` values (`repeat(auto-fit, minmax(...))` and a bare `1fr 1fr`) that don't reserve `minmax(0, ...)` on their tracks, which let a long first-column content item claim more width than its share and push the second column into negative/zero space — the standard CSS grid/flexbox "won't shrink below content size" trap, same root cause (just a different symptom) as a bug fixed in the previous pass's executive-summary layout.
